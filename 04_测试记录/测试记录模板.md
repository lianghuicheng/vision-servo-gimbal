## 一、端到端延迟测量（最重要的指标）

### 测量原理

延迟 = **目标变化的那一刻** → **执行器真正动起来的那一刻**。

### 三种测法（按可行性排序）

**方法 A：毫秒计时器拍摄法（最简单，W4 就能做）**
1. 手机上打开一个毫秒计时器 App，放在摄像头前
2. 让云台/舵机去追计时器上的某个位置，或用软件让视觉发出一个跳变目标
3. 用第三个设备（另一台手机）**慢动作录像**（240 fps 足够）
4. 逐帧看：视觉发出指令的那一帧 vs 舵机开始动的那一帧，数帧数 ÷ 帧率 = 延迟

**方法 B：GPIO 翻转 + 逻辑分析仪法（最准，W13 推荐）**
1. 视觉端识别到目标后，让 STM32 在一个空闲 GPIO 上翻转电平（标记"收到坐标"）
2. 驱动舵机的 PWM 通道同时接到逻辑分析仪
3. 逻辑分析仪上看：GPIO 翻转 → PWM 占空比开始变化，两点时间差 = 控制链路延迟
4. 视觉处理延迟 = 总延迟 − 控制链路延迟（在 Python 端用 `time.perf_counter()` 打点算）

**方法 C：软件打点法（最方便，但只测到"发出"为止）**

```python
import time
t0 = time.perf_counter()      # 采集到这一帧
frame = cap.read()
t1 = time.perf_counter()      # 采集完成
t = find_target(frame)
t2 = time.perf_counter()      # 识别完成
ser.write(pack_target(...))
t3 = time.perf_counter()      # 发送完成
print(f"采集 {(t1-t0)*1000:.1f}ms | 识别 {(t2-t1)*1000:.1f}ms | 发送 {(t3-t2)*1000:.1f}ms")
```

### 优化手段清单（做完一项填一次表）

- [ ] 降低分辨率（640×480 → 320×240）
- [ ] ROI 裁剪（只在目标可能出现区域处理）
- [ ] 减少 `cvtColor` 次数（一次转 LAB 复用）
- [ ] 用 `cv2.findContours` 前先降采样 mask
- [ ] 关闭 `cv2.imshow`（显示很耗时间，比赛时关掉）
- [ ] 提高波特率（115200 → 460800）
- [ ] 精简协议载荷
