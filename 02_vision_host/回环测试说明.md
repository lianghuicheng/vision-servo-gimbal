# 串口回环测试（W1 核心验证：不需要写任何固件）

> **先看这条**：如果 STM32 板子上**已经烧了会回传数据的固件**，可以跳过本文的短接步骤 ——
> 直接发一条它认识的指令，看它回不回话，这比"线自己接自己"更有价值。
> 一条命令验证：
> ```powershell
> python sniff_port.py COM4 --send "R,120,80,45,60\r\n" --seconds 3
> ```
> 若板子回出 `color=R x=120 y=80 w=45 h=60` 之类内容，说明**双向链路完全正常**。
> 本文的短接回环仍值得做一次，用它在**高波特率下测物理层误码率**。

原理：把串口的发送线和接收线短接起来，电脑发出去的数据会原样回到电脑。
这样就能**单独验证**「Python 代码 + 驱动 + 串口线 + 波特率」这一条链路，
把"通信的问题"和"STM32 固件的问题"彻底分开排查。

## 三种做回环的方式（选一个）

**方式 A：USB-TTL 模块（最干净）**
用一根杜邦线（或镊子）把模块的 **TXD 和 RXD 短接**，插到电脑。
→ 出现一个 COM 口，直接跑下面的命令。

**方式 B：用 STM32 开发板的板载 CH340（不写固件）**
正点原子 MiniSTM32 上，板载 CH340 的 TXD 接 PA10、RXD 接 PA9。
用一根杜邦线把 **PA9 和 PA10 短接**，USB 线连电脑。
→ PC 发出 → CH340 → PA10 → 跳线 → PA9 → CH340 → 回到 PC。
⚠️ 前提是板上固件没有在用 USART1 收发，否则会打架。如果不放心，先按一下复位键。

**方式 C：两块 USB-TTL 交叉互连**
A 的 TXD 接 B 的 RXD，A 的 RXD 接 B 的 TXD，共地。一个口发，一个口收。

## 运行

```powershell
cd D:\电赛学习\04_主线作品_视觉伺服云台\02_vision_host

# 先看有哪些串口
python serial_hello.py --list

# 跑回环测试（默认发 200 帧）
python loopback_test.py --port COM5

# 加大压力：发 1000 帧，提高波特率
python loopback_test.py --port COM5 -n 1000 --baud 460800

# 故意制造误码：不短接 TX/RX，应该收到 0 帧 —— 这能验证你的统计是对的
python loopback_test.py --port COM5 -n 50
```

## 判定标准

| 结果 | 含义 |
|---|---|
| **回环成功率 100%** | 链路完全正常，可以进入下一步（连 STM32） |
| 成功率 95~99% | 波特率偏高或线太长，降到 115200 再试 |
| 成功率 0% | TX/RX 没短接，或端口选错，或被 XCOM 占用 |
| 一帧都收不到但端口能打开 | 串口被别的程序占用了（**同一个串口只能被一个程序打开**） |

## 常见坑

| 现象 | 原因 |
|---|---|
| `串口错误：拒绝访问` | XCOM / 串口助手还开着，先关掉 |
| 收到乱码 | 波特率不一致，或没共地 |
| 收到的字节数忽多忽少 | 正常，串口是流式设备，所以协议才需要帧头+长度+CRC |
| 短接后 STM32 发烫 | **别短接电源引脚！** 只短接 TXD/RXD（或 PA9/PA10） |
